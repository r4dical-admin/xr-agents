# Experimental One Pro head tracking

Connect the One Pro directly by USB-C. Enable Ethernet in the glasses developer menu, and select flat Follow display mode (disable onboard Anchor to avoid applying rotation twice). Launch the Electron app, click CONNECT XREAL and hold the glasses still until calibration finishes. Face forward and click RECENTER. Disconnect returns to mouse simulation.

The trusted Electron process discovers link-local peers and connects to TCP port 52998. It decodes fragmented 134-byte frames, validates sensor values and timestamps, estimates stationary gyro bias, and integrates a normalized quaternion with gravity feedback. Only orientation and status cross the isolated preload. Connection loss triggers retries; missing or stale samples hold the last view instead of jumping to the cursor. Disconnect tracking to use right-button drag simulation.

This is an original experimental implementation based on the wire-format observations in [AR Glass Lib](https://github.com/taowen/ar-glass-lib) and the [community network IMU driver](https://github.com/dripster82/ar_workspace_manager_for_xreal/blob/main/Sources/CXrealDriver/src/device_imu_net.c). No source was copied from the noncommercial macOS application.

Automated tests verify parser resynchronization, fragmented frames, both known headers, invalid measurements, stationary calibration, yaw integration, quaternion normalization and recentering. No One Pro USB Ethernet interface was attached during implementation, so axis signs, mount tilt, latency and perceived world stability still require physical hardware validation. Calibration records the resting gravity direction; it is not a factory-calibrated optical mount transform.

Rotation only: yaw can drift and needs occasional recentering. No positional 6DoF, XREAL Eye pose, stereoscopic compositor or native XR prediction is implemented. This is a level panoramic desktop surface, not a calibrated stereo XR renderer. Roll is suppressed. Camera and panels share a 25 ms exponential orientation filter, independent of frame rate. Looking left now moves the viewport left across the workspace; looking right moves it right. Panel panning uses focal-length × tan(angle), with screen Y matching Three.js projection. Angles clamp before projection at the panoramic workspace edges to avoid reversing past 90 degrees. Beyond an edge, the workspace stops moving; it is not an unlimited world-anchored canvas. Correct perceived angular scale still requires a physical-glasses test.
